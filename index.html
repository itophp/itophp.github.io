AI-Native Application Framework

让人和 Agent，
围绕同一套业务能力协作

业务动作只注册一次。页面按钮、Agent 工具、流程节点和外部 API 经过同一个 Capability Gateway 执行，共享权限、审批与执行记录。

一切经过 Gateway

权限、风险分级、审批与审计是代码里的确定性规则，不依赖模型自觉。以下为纯前端交互演示，行为规则来自框架文档。

任务闭环

一次任务从意图到结果的六个环节。

  • 01理解目标 · 识别完成条件
  • 02建立上下文 · 身份与授权对象
  • 03组织行动 · 流程内推进
  • 04执行能力 · 经 Gateway 调用
  • 05处理变化 · 暂停或交给人
  • 06确认结果 · 事件驱动后续

风险 × 发起方：审批矩阵

人类点击可执行 high 风险动作；Agent / Workflow / 事件 / API 发起的 high 必须人工确认；critical 对自动化关闭。

风险等级人（页面）Agent / Workflow事件 / API

能力契约，写在代码里

框架里没有「配置出来的动作」。每一项业务能力都是显式声明的 Go 代码，随代码评审和测试交付。

声明即契约。右侧是示例模块中真实注册的只读能力：权限 example:read、低风险自动批准、输入只接受一个正整数，输出投影明确到字段，只有 id 允许进入日志。

页面按钮、Agent 工具或流程节点调用它时，走的是同一条 Gateway 路径——不存在第二套业务规则。

        "id": {Type: "integer"}, "title": {Type: "string"},
        "status": {Type: "string"}, "ready": {Type: "boolean"},
    }, "id", "title", "status", "ready"),
    Loggable: []string{"id"},
}
