Horizon · 开源 AI 原生企业应用框架

为业务用户减负的 AI 原生应用框架

用 Horizon 构建企业应用，把 AI 辅助嵌入表格、表单、详情页和工作流。用户打开列表就能按需分析风险，录入时可以核对并采纳字段建议，也可以把多步任务交给 Agent 推进。

从底层开始，页面、Agent 和 Workflow 就共用业务能力。业务代码负责计算、权限和状态变更，AI 帮助提取信息、解释差异和准备操作，用户负责复核与关键决定。

从当前业务界面到受控执行

AI 辅助由业务界面和业务契约共同定义。开发者配置任务所需的上下文和可用动作，用户在处理记录时触发辅助，系统按当前身份执行。

  1. 读取当前业务上下文

    业务元数据描述记录有哪些字段、和什么对象关联、处于什么状态。Application Runtime 的 Provider 读取当前身份有权访问的数据，AI 组件和 Agent 分析按配置取得所需字段。

    分析可以基于当前记录和指定的关联数据，用户能看到结论、依据和分析覆盖范围。

    业务元数据与契约

  2. 选择可执行的业务动作

    开发者注册查询、创建、提交或状态变更等能力，声明版本、参数和风险。页面按钮和 Agent 工具引用同一项能力，工具可用性取决于当前身份、来源和业务策略。

    Gateway 依据能力契约校验参数与权限，执行器按业务规则处理记录与数据范围。

    Registry 与能力契约

  3. 推进任务并交给人确认

    Workflow 定义步骤依赖、条件分支和等待点。Graph 可组织有界分析或循环，ADK Agent 在限定的工具和迭代预算内处理需要判断的步骤。

    触发确认策略时，系统记录待审批调用并暂停。审批通过后重新核验原申请人的授权，再按原方案继续。

    任务编排与人工参与

  4. 用业务结果完成反馈

    页面可以读取更新后的状态，任务可以根据能力返回的结构化结果继续。执行记录保留调用进度和结果，帮助用户确认哪些操作已完成、哪些仍在等待。

    符合规则的业务事件进入事件链路，触发后续任务。后续任务的业务动作继续经 Gateway 执行。

    执行、审计与事件

框架提供哪些基础能力

Registry 与 Business Metadata Engine
业务模块声明实体、关系和状态转移，并将可执行动作及其 Schema 注册到能力目录。实体声明可以对照数据库迁移校验。页面和 Agent 可以由此理解同一个业务对象，并按契约引用动作。
Gateway、Workflow 与 Graph
调用经过身份、授权、参数、审批策略与幂等检查。简单操作由 Direct 执行，多步任务交给 Workflow，受限分析可用 Graph。能力编排中心管理已注册执行方案的发布、绑定和回滚。
Application Runtime
配置导航、列表、表单和详情，把查询绑定到 Provider、把提交绑定到 Action。团队可以预览应用配置、审查差异并发布版本，也可以把 AI 分析和表单辅助嵌入相应页面。
Memory Center
汇集业务事件与任务运行元数据，支持按授权范围维护记忆、追溯来源和记录纠正。自动提炼和在 Agent 任务中直接使用记忆属于后续方向。
Plugin 插件
通过插件交付实体、能力、权限、事件和应用界面。宿主校验版本与依赖，并将插件贡献接入共享目录。业务团队可以扩展自己的模块，也可以让已有能力供多个入口复用。

从录入到执行，五类可组合的 AI 辅助

按岗位和业务环节选择需要的辅助。可以只在一个列表增加分析，也可以把核对、方案准备和人工确认组织进同一个任务。

查看现有组件、配置方式和扩展范围

辅助录入 · AI Input
把工作簿内容转换为可编辑的业务草稿，或根据表单已填字段起草描述。用户校对后再提交，应用负责校验字段和写入。
辅助核对 · AI Check
先由规则找出数量、金额或状态差异，再由 AI 辅助归类和解释，帮助用户优先复核异常。这是面向对账与业务检查的扩展方向。
辅助分析 · AI Analyze
在列表和详情中根据配置的字段生成风险摘要与依据。进一步的报表分析可以用来组织跨模块证据，并标明口径、期间和可能原因。
辅助决策 · AI Suggest
面向库存、采购等场景，可按成本、时效与业务约束组织备选方案。业务人员核对依据后选择方案。这是应用设计方向。
受控执行 · AI Act
Agent 或 Workflow 可以发起已授权的能力调用。涉及写入时可先准备草稿，按业务策略由用户提交或审批，再由领域逻辑执行。

用于 ERP 的三个设计场景

采购、财务和库存的业务模块提供数据、规则和执行能力。试点可以对比使用 AI 辅助前后的人工耗时、返工与正确率，评估用户具体少做了哪些工作。

采购 · 优先核实交付风险

用承诺日期和生产需求筛选可能影响交付的订单。AI 辅助列整理历史交付记录和风险依据，采购员优先核实异常，再决定是否催交或调整计划。

试点评估 每日检查耗时、误报和漏报。

财务 · 缩短月结差异排查

业务查询按期间、金额和单据状态找出入库未匹配发票等差异。AI 归类异常、整理凭证和可能原因，财务人员复核处理建议，分录与关账由领域逻辑执行。

试点评估 异常定位时间、核对正确率与证据覆盖。

库存 · 对比缺料处理方案

根据可用库存、交期和物料替代规则准备调拨、替代或采购方案。AI 整理各方案的时效和约束，业务人员决定采取哪项动作，库存变更经过授权和校验。

试点评估 方案准备时间、人工步骤数与返工率。
