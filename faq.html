常见问题

关于 Horizon 的定位、许可证、成熟度与参与方式。答案以仓库文档为准。

Horizon 是什么，不是什么？

Horizon 是面向企业应用的 AI 原生框架：把业务实体、Schema 契约、可执行能力、智能决策、流程编排、人工参与和业务事件组织成一个整体，让 Agent 在明确的权限与业务边界内推进工作。

它不是现成的业务系统，也不是无代码搭建平台。业务模块（文章、示例应用等）用于验证框架机制；真实的业务语义、规则与集成仍通过工程开发和验证交付。

「AI-Native」在这里具体指什么？

指让智能参与成为应用的运行机制，而不是附加的聊天窗口：应用向 Agent 提供业务语义、可信上下文、可执行能力和持续的任务状态；Agent 在治理边界内把目标转化为行动；应用再以真实业务结果回应。

具体体现为六点：业务可理解、能力可发现可组合、决策可协作、执行可治理、过程可持续、结果可反馈。

和常见的低代码 / 工作流平台有什么区别？

核心区别是单一能力契约：业务动作只注册一次，页面按钮、Agent 工具、Workflow 节点和外部 API 都经过同一个 Capability Gateway 执行，共享权限、审批与执行记录。

大多数平台为每个入口维护各自的业务规则与权限模型；Horizon 中编排只是组织工作的方式——流程启动和每个业务节点仍必须经过 Gateway 授权。

采用什么开源协议？可以商用吗？

项目采用 GPL-3.0-or-later。你可以自由使用、修改和分发，但分发衍生作品时必须同样以 GPLv3 开源并提供完整对应源码。

将本项目作为网络服务对外提供时，GPLv3 不要求向服务使用者开放源码；如需覆盖该场景，应改用 AGPL-3.0。第三方依赖中 Eino、MCP Go SDK 为 Apache-2.0，Goa、shadcn、MDXEditor 等为 MIT，均与 GPLv3 兼容。

项目的成熟度如何？哪些还没实现？

框架机制与具体业务接入有各自的成熟度，概念图不表示所有场景都已开箱即用。当前支持范围、已知限制与验证记录保留在工程验收记录等文档中。

部分仍在建设中的能力：Memory Center 的自动提炼、向量检索与自动清理；编排画布的完整在线 DSL 保存与灰度发布等。文档中会明确区分「已实现 / 已验证 / 待决策」。

Agent 会不会越权执行危险操作？

不会——权限、风险等级、审批和深度限制是代码里的确定性规则，不是模型承诺。人类点击可执行 high 风险动作；Agent、Workflow、事件和 API 发起的 high 风险动作必须人工确认；critical 对自动化完全关闭。

审批通过后使用申请人身份重建执行；工具 Schema、页面注册和模型输出都不能替代服务端授权。Agent 不能批准自己的权限。

如何参与贡献？

先阅读 AGENTS.md 了解架构边界，按任务工具矩阵选择对应的开发流程。提交前使用快速门禁验证：

make ci-fast（无需数据库与浏览器）；触及表结构时加 make test-integration。文档变更运行 make check-rules。

注意：推送或开 PR 会触发远程 CI 的全量 E2E；完整浏览器集合在本地默认暂停，执行前需要确认授权范围。

部署时有哪些安全注意事项？

初始账号不提供通用默认密码，由 make bootstrap 以环境变量创建。公网部署要求 HTTPS 和 COOKIE_SECURE=true；会话为 8 小时 HttpOnly cookie，写请求校验 Origin + CSRF；密码使用 Argon2id。

启用加密配置需提供 SETTINGS_ENCRYPTION_KEY；附件目录受 FILE_STORAGE_ROOT 限制；SMTP 主机须加入白名单。数据库、存储目录与加密根密钥须配套备份。
