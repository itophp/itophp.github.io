使用 Horizon CLI 快速开始

先离线看懂一个业务动作如何注册，再启动前后端，在页面里体验 Agent 初筛与人工复核。

构建 CLI

准备 Go 1.27.3。运行完整应用还需要 Node.js ≥ 22.23.2、pnpm 10.14.0，以及用于本地 PostgreSQL 的 Docker Compose。已有 PostgreSQL 时可以通过 DATABASE_URL 使用自己的实例。

Shell
git clone https://github.com/itophp/horizon.git
cd horizon
go build -trimpath -o horizon-cli ./foundation/cmd/horizon-cli

Windows PowerShell 可用 go build -trimpath -o horizon-cli.exe ./foundation/cmd/horizon-cli，后续命令使用 .\horizon-cli.exe。仓库自带的二进制可用于快速浏览，源码有更新时重新构建再查看注册定义。

离线查看能力与流程

下面的命令可在前后端和数据库停机时使用。先查能力输入与权限，再看流程节点如何引用它，最后查看文章详情页怎样绑定动作。

Shell
./horizon-cli capability schema article.submit@1.0.0
./horizon-cli workflow schema article-publish@1.0.0
./horizon-cli page schema articles/article.detail@2.0.0

输出为 JSON。schema 描述定义的结构，entry.definition 是选中的注册定义。当前环境的租户版本和实际权限在运行时生效。

准备本地服务

首次启动前安装依赖、启动 PostgreSQL、应用迁移并创建管理员。请在仓库根目录运行以下命令，使用本地开发数据库。

Shell
cp .env.example .env
pnpm install --frozen-lockfile
make db-up
make migrate

已有 PostgreSQL 时，可跳过 make db-up。在执行迁移前，用 ./horizon-cli env configure 写入本地配置，或在进程环境中设置 DATABASE_URL。

输入一个 12–128 字符的初始密码。以下命令适用于 Bash 和 Zsh。

Shell
read -s BOOTSTRAP_PASSWORD
export BOOTSTRAP_PASSWORD
BOOTSTRAP_USERNAME=admin make bootstrap
unset BOOTSTRAP_PASSWORD

若要体验文章发布，在启动前为本地 .env 配置 SETTINGS_ENCRYPTION_KEY，用于保存模型凭证。运行 env check 检查依赖和数据库连通性，处理报出的必需项后再启动 Go API 与 Vite。

Shell
./horizon-cli env check
./horizon-cli start
./horizon-cli status

打开 本地登录页，用新建账号登录。可访问 API health 检查 API 进程是否存活，数据库连通性看 env check。

体验文章发布与复核

  1. 准备模型和权限

    进入系统设置，发布 agent.enabled、agent.baseUrl、assistant.model 和 assistant.token。提交账号需要文章读写、流程运行和 AI 使用权限。准备具备 capability:approve 的账号处理发布确认。

  2. 提交一篇测试文章

    进入文章应用，新建一篇测试文章，并从详情页提交。观察 Agent 初筛和流程状态。初筛通过后，流程会等待发布确认。用具备审批权限的账号在 AI 工作台（/ai）查看并处理待确认动作。进入工作台也需要 assistant:use。

  3. 确认业务结果

    返回文章详情与流程记录，核对审核结果、最终状态以及执行进度。未配置模型时，可以先用离线目录查看流程结构。

查看状态、重启与停止

Shell
./horizon-cli status
./horizon-cli restart backend
./horizon-cli stop

进程状态与日志保存在 .local/horizon-cli/。这些服务命令只管理由 CLI 启动的前后端。
